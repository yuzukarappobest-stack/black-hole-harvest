# カートレース 3D

学習アプリの「ごほうびゲーム」から選べる、Three.js 製の独立した周回レースです。

- ループ状のサーキットを 3 周
- 自車 1 台 + CPU 5 台。CPU は走行ライン・コーナー減速・追い越しを制御
- 自動アクセル、左右への傾きハンドル。ブレーキは廃止してダッシュボタンを搭載
- 1周に2個のダッシュアイテムを配置。取るとチャージを1つ獲得（最大2つ）。使用すると2.8秒間加速し、次の周回でアイテムが復活
- iOS Safari の DeviceOrientation 許可（スタートタップで要求）およびハンドルの再中心化
- 傾きが使えない場合：路面画面を左右ドラッグ。PC：左右キー/A・D、Space でダッシュ
- 走行速度・順位・ラップ・タイム・ミニマップ・ベストタイム
- コースアウトすると速度が落ちる。誤った自動復帰を避けるため強制ワープを廃止
- 本当に道から大きく外れた状態が3秒続いたときだけ「コースにもどる」ボタンを出す。プレイヤーが押した場合に限って2.5秒ペナルティ付きで復帰
- CPU が先にゴールしても自車が3周終えるまでプレイ継続
- 既存の \`miniGameAccess:kart-race\` を消費する1回限りのごほうびゲーム。終了後は学習メニューへ戻る

## 実装

- \`index.html\` / \`style.css\`：スマホUI
- \`track.js\`：閉じた Catmull-Rom サーキット、路面、縁石、景色、距離・コース投影
- \`controls.js\`：傾き入力・再キャリブレーション・ドラッグの代替・ブレーキ
- \`game.js\`：3D レンダリング、カート、CPU、物理・順位・周回、HUD

Three.js 0.164.1 を CDN から ES module で読みます。静的サイトとして配信できます。

## 重要な確認項目
1. 学習完了後、ごほうびゲームで「カートレース 3D」を選べる。直接URLを開いても遊べない。
2. iPhoneでSTARTを押し、傾きの許可を与えた後、傾きに応じて旋回する。横向きと縦向きを試す。
3. コース上の光るアイテムを集め、ダッシュボタンで加速。2つまでチャージでき、次の周回で再取得できる。
4. CPU5台が周回し、追い抜くと順位が入れ替わる。ミニマップの印も進む。
5. 1周、2周、3周でラップ表示が進み、3周のフィニッシュ後に結果画面が出る。
6. 背景から戻った際に一時停止できる。結果画面から「がくしゅうへ もどる」で戻れる。
7. iPhoneの実機で FPS・メモリ・操作方向・路外判定を確認する。

## 留意点
Playwright/実機での操作感の最終確認がまだ必要です。既存の「レース」は従来のまま残しています。

## ダッシュ機能（追加）
- `items.js`：周回ごとに復活する光るアイテムの配置・描画・接触判定
- `driving.js`：通常速度42、ダッシュ中の目標速度66の加速・減速
- `controls.js`：iPhoneの傾き操作は従来どおり。PCのスペースキーはブレーキからダッシュに変更
- ダッシュの使える時間：2.8秒。チャージ中・発動中はボタンの表示が変化

## v9：周回と順位の修正
- `progress.js` に距離追跡を分離。測位位置が不連続になったときも進行記録用の基準位置・セグメント番号を再同期する。
- ローカル投影が古い場合はコース全体から取得した最近接位置を採用する。移動量の上限で誤カウントを防ぎ、計測が永続的に止まる問題を防止する。
- 順位・周回・ゴール・周回ごとのダッシュアイテムは、修正後の共通進行記録を参照する。
- ゲーム開始画面に「v9」と表示し、ゲーム一覧およびJSの読み込みURLを変更。端末で最新版が読み込まれたか確認しやすくする。

## v10：周回計測の追加修正
- 一時的な誤測位（1〜2フレーム）を無視し、進行度を失わない。
- 誤測位が継続する場合は3回目で実際の道路位置に再同期し、永続的な停止を防ぐ。
- スタートライン前からの出走と3周目ゴールの境界、逆走、誤測位を単体試験。
- キャッシュ対策のバージョン表示・読み込みURL更新。

## v11：iPad傾き操作対応
- フルーツラッシュと同じ `deviceorientation.gamma` だけでハンドル操作を計算。
- `screen.orientation.angle` の値による `beta` 軸への切替を廃止。iPadの画面向き報告に左右されず操作方向が一定になる。
- センサー利用開始時・画面回転時に中立位置を再設定し、端末を平常の持ち方に戻してからの意図しない旋回を防止。
- 既存のハンドル調整ボタン・ドラッグ操作は維持。iPhoneとiPad両方で実機確認要。

## v12：ショートカット対策
- 道幅22、左右それぞれ芝生5.5mを残し、その先に赤白ガードレールを連続配置（`track.js`）。
- `barriers.js`：ガードレール越えを物理的に防止。軽い接触減速と0.65秒クールダウン。操作方向は維持。
- `checkpoints.js`：1周18個、計54個の順序付きチェックポイントを実際の横断で確認。飛ばした地点は加算しない。
- プレイヤーの順位・周回・ゴールはチェックポイント検証済み進行度から計算。近くの道路へ飛んでもショートカット成立せず。
- iPadの傾き操作、CPU5台、ダッシュアイテム2個/周を維持。v12に更新しキャッシュを無効化。

### 検証項目
- 内側・外側ガードレールへ正面から当たっても通過しない。
- 道路とレール間の芝生でハンドル操作を続けられる。
- 途中区間を飛ばしても順位が上がらない。
- 18区間×3周を順番に走るとゴールする。
- iPad/iPhoneで表示・動作を確認（実機確認は別途）。

## v14：第2コース「サンセット・サーキット」
- ごほうびゲーム一覧に「みどり（従来）」と「サンセット（新コース）」の2件を表示。従来コース形状やCPU速度は変更なし。
- サンセットは長い直線、S字カーブ、大きなコーナーを備える別形状の周回コース。夕焼けの背景、暖色の芝生、青白ガードレールで区別する。
- 両コースとも3周、CPU5台、道幅22、片側5.5mの芝生、両側の衝突ガードレール、18地点×3周のチェックポイント方式、ダッシュアイテム2個/周。
- 第2コースだけ紫色の「チャンピオン」CPU1台が通常最高速度42で走る（プレイヤーのダッシュなし最高速度42と同じ）。他の4台は従来の速度、コース1の5台も変更なし。
- コースごとにベストタイムを別保存。
- iPad画面を回転させるv13の処理は戻したまま。コース選択はゲーム一覧で実施し、従来の1回のごほうびにつき1回プレイの制限を維持。

## v15：両コースのゴール判定を修正
- レース開始時のスタートライン通過を最初のチェックポイントとしてカウントするため、3周目のゴールを認定するには18×3+1=55回のゲート通過が必要。従来の54回では最後の1区間前に終了していた。
- 順位・周回の進行値がゴール直前まで進んでも、3周目の実際のゴールラインを横切らない限りレース終了しない。
- 元のコース・サンセットの両コースで早期ゴールが発生しないことを計算テストで確認。
- 配信キャッシュを更新して開始画面にv15表示。

## v16：第3コース「クリスタル・スイッチバック」
- ごほうびゲーム一覧に「クリスタル」を独立追加（`kart-race/?course=3`）。コース1・2を維持。
- つづら折りの長い3本の直線・連続ヘアピン・S字シケインを備える高難度コース。水色の地面、濃紺の道路、青緑／白のガードレール、路面から離して配置した氷結晶の装飾で区別。
- 片側芝生5.5m、道幅22、衝突ガードレール、1周18地点の通過判定、3周ゴール、ダッシュアイテム2個を継承。
- 第3コースにも紫色のチャンピオンCPUを1台配置（通常時のプレイヤーと同じ最高速度42）。他4台は通常速度。コース1・2のCPU設定は維持。
- 第3コース用のアクセス権 `miniGameAccess:kart-race-3` とベストタイム `kartRaceBestTime3` を分離。学習後の1回遊べる制約を維持。
- iPad向けの画面回転処理は復活させず、従来のv12以降の操作のまま。
